1. What we’ll use (Servlet standard way)

Java already gives you a session system:

HttpSession (server-side session storage)

Cookie-based session ID (JSESSIONID)

Container-managed lifecycle (Tomcat/Jetty/etc.)

👉 You do NOT need to invent your own session IDs.

3. Login flow (creating a session)
LoginServlet.java
@WebServlet("/login")
public class LoginServlet extends HttpServlet {

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        String username = req.getParameter("username");
        String password = req.getParameter("password");

        // 1. Validate credentials (pseudo-code)
        User user = UserDAO.authenticate(username, password);

        if (user != null) {
            // 2. Create session
            HttpSession session = req.getSession(true);

            // 3. Store user info in session
            session.setAttribute("user", user);
            session.setAttribute("role", user.getRole());

            // 4. Set session timeout (in seconds)
            session.setMaxInactiveInterval(30 * 60); // 30 minutes

            resp.sendRedirect("dashboard.jsp");
        } else {
            req.setAttribute("error", "Invalid credentials");
            req.getRequestDispatcher("login.jsp").forward(req, resp);
        }
    }
}

Key points

getSession(true) → creates session if none exists

Session ID is stored in JSESSIONID cookie automatically

Store minimal data in session (id, username, role)

5. Authentication filter (BEST PRACTICE)

Never check auth inside every JSP.

AuthFilter.java
@WebFilter("/*")
public class AuthFilter implements Filter {

    private static final Set<String> PUBLIC_PATHS = Set.of(
        "/login.jsp",
        "/login",
        "/css/",
        "/js/"
    );

    @Override
    public void doFilter(
            ServletRequest request,
            ServletResponse response,
            FilterChain chain)
            throws IOException, ServletException {

        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse resp = (HttpServletResponse) response;

        String path = req.getRequestURI()
                         .substring(req.getContextPath().length());

        boolean isPublic = PUBLIC_PATHS.stream()
                .anyMatch(path::startsWith);

        HttpSession session = req.getSession(false);

        boolean loggedIn = session != null && session.getAttribute("user") != null;

        if (loggedIn || isPublic) {
            chain.doFilter(request, response);
        } else {
            resp.sendRedirect(req.getContextPath() + "/login.jsp");
        }
    }
}


Now:

All protected pages are secure

One central auth rule

Very framework-like behavior

6. Logout flow
LogoutServlet.java
@WebServlet("/logout")
public class LogoutServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        HttpSession session = req.getSession(false);
        if (session != null) {
            session.invalidate();
        }

        resp.sendRedirect("login.jsp");
    }
}


What this does:

Deletes server-side session

Browser cookie becomes useless

User is fully logged out

7. Session expiry (idle timeout)

Already handled by:

session.setMaxInactiveInterval(30 * 60);


Also configurable globally in web.xml:

<session-config>
    <session-timeout>30</session-timeout> <!-- minutes -->
</session-config>

8. Security hardening (IMPORTANT)
Force HTTPS cookie settings (Tomcat example)
<cookie-config>
    <http-only>true</http-only>
    <secure>true</secure>
</cookie-config>

Prevent session fixation

Always invalidate old session on login:

HttpSession oldSession = req.getSession(false);
if (oldSession != null) {
    oldSession.invalidate();
}

HttpSession newSession = req.getSession(true);

9. What NOT to do (common mistakes)

❌ Store password in session
❌ Put large objects in session
❌ Manually manage cookies for auth
❌ Skip session invalidation on login
❌ Auth logic inside JSPs
