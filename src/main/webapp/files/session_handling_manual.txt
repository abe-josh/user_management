Big picture (what you’re replacing)

When you write:

HttpSession session = req.getSession();


the servlet container secretly does this:

Request →
  read Cookie: JSESSIONID=abc123 →
  find session object in memory →
  attach it to request


We’ll now do that manually using:

Cookies

A session store (Map)

Filters

Explicit expiry logic

Step 1: Define what a session REALLY is

A session is just:

sessionId (random) → sessionData (Map) → expiryTime


Let’s create that.

Session.java
public class Session {
    private String sessionId;
    private Map<String, Object> data = new HashMap<>();
    private long lastAccessedTime;

    public Session(String sessionId) {
        this.sessionId = sessionId;
        touch();
    }

    public void touch() {
        this.lastAccessedTime = System.currentTimeMillis();
    }

    public long getLastAccessedTime() {
        return lastAccessedTime;
    }

    public Object getAttribute(String key) {
        return data.get(key);
    }

    public void setAttribute(String key, Object value) {
        data.put(key, value);
    }
}

Step 2: Create a session store (the “server memory”)

This is what Tomcat normally manages internally.

SessionStore.java
public class SessionStore {

    private static final Map<String, Session> sessions = new ConcurrentHashMap<>();
    private static final long SESSION_TIMEOUT = 30 * 60 * 1000; // 30 min

    public static Session get(String sessionId) {
        Session session = sessions.get(sessionId);

        if (session == null) return null;

        long now = System.currentTimeMillis();
        if (now - session.getLastAccessedTime() > SESSION_TIMEOUT) {
            sessions.remove(sessionId);
            return null;
        }

        session.touch();
        return session;
    }

    public static Session create() {
        String sessionId = UUID.randomUUID().toString();
        Session session = new Session(sessionId);
        sessions.put(sessionId, session);
        return session;
    }

    public static void invalidate(String sessionId) {
        sessions.remove(sessionId);
    }
}


💡 This is the core of session management.

Step 3: Read & write cookies manually
Read cookie
public static String getCookie(HttpServletRequest req, String name) {
    if (req.getCookies() == null) return null;

    for (Cookie cookie : req.getCookies()) {
        if (cookie.getName().equals(name)) {
            return cookie.getValue();
        }
    }
    return null;
}

Write cookie
public static void addSessionCookie(HttpServletResponse resp, String sessionId) {
    Cookie cookie = new Cookie("MYSESSIONID", sessionId);
    cookie.setHttpOnly(true);
    cookie.setSecure(true); // HTTPS only
    cookie.setPath("/");
    resp.addCookie(cookie);
}

Step 4: Authentication filter (manual session resolution)

This replaces req.getSession().

SessionFilter.java
@WebFilter("/*")
public class SessionFilter implements Filter {

    @Override
    public void doFilter(ServletRequest request, ServletResponse response,
                         FilterChain chain)
            throws IOException, ServletException {

        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse resp = (HttpServletResponse) response;

        String sessionId = CookieUtil.getCookie(req, "MYSESSIONID");

        Session session = null;
        if (sessionId != null) {
            session = SessionStore.get(sessionId);
        }

        if (session != null) {
            req.setAttribute("session", session);
        }

        chain.doFilter(request, response);
    }
}


Now every request has access to the session (if any).

Step 5: LoginServlet (fully manual session creation)

Now we rewrite your servlet without HttpSession.

LoginServlet.java
@WebServlet("/login")
public class LoginServlet extends HttpServlet {

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        String username = req.getParameter("username");
        String password = req.getParameter("password");

        User user = UserDAO.authenticate(username, password);

        if (user != null) {
            // 1. Create session
            Session session = SessionStore.create();

            // 2. Store auth data
            session.setAttribute("user", user);
            session.setAttribute("role", user.getRole());

            // 3. Send session id to browser
            CookieUtil.addSessionCookie(resp, session.getSessionId());

            resp.sendRedirect("dashboard.jsp");
        } else {
            req.setAttribute("error", "Invalid credentials");
            req.getRequestDispatcher("login.jsp").forward(req, resp);
        }
    }
}


🎯 You have now fully replaced HttpSession.

Step 7: Logout (manual invalidation)
@WebServlet("/logout")
public class LogoutServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {

        String sessionId = CookieUtil.getCookie(req, "MYSESSIONID");

        if (sessionId != null) {
            SessionStore.invalidate(sessionId);
        }

        Cookie cookie = new Cookie("MYSESSIONID", "");
        cookie.setMaxAge(0);
        cookie.setPath("/");
        resp.addCookie(cookie);

        resp.sendRedirect("login.jsp");
    }
}

Step 8: What you just learned (THIS is the gold)

You now understand:

✔ Cookies are just key/value pairs sent by the browser
✔ Session IDs are pointers, not user data
✔ Sessions live only on the server
✔ Expiry = timestamp comparison
✔ Logout = delete session + delete cookie
✔ HttpSession is just a convenience wrapper

This is exactly how:

Tomcat

Spring Session

Express.js

Django

…work internally.
